# Работа с планом реализации

- Перед реализацией задачи прочитай `IMPLEMENTATION_PLAN.md` и соответствующие разделы `backend/README.md` и `frontend/README.md`. Источник истины для предметных правил — `backend/README.md`.
- Выполняй небольшие связанные сценарии по циклу: контракт API → backend и его проверки → frontend и его проверки. Все контракты заранее не проектируй.
- Обновляй `IMPLEMENTATION_PLAN.md` в том же наборе изменений, что и реализацию соответствующей задачи или её части.
- После завершения задачи замени её исходное описание кратким отчётом на том же месте. Сохрани ID и название, отметь выполнение и укажи дату, реализованное поведение, фактические проверки и оставшуюся работу или ограничения. Следуй формату в плане.
- Для частично выполненной задачи сохрани исходный объём, добавь текущий результат и оставшуюся работу; не отмечай её завершённой. Обнови статус блока в общей таблице.
- Не заявляй о проверках, которые не выполнялись. Если проверка недоступна, явно укажи это в отчёте.
- В финальном ответе после реализации кратко сообщай, что удалось сделать, как проверено и что осталось.
